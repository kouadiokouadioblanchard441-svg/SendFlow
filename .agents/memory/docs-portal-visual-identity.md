description: User-required relationship between the API documentation portal and SendFlow legal-page visual style.

Use the supplied API-documentation reference's Inter typography while retaining the SendFlow palette: pure white `#fff`, ink `#17181d`, body text `#292a30`, violet `#8b4cc8` (deep `#7736b5`), and lavender surfaces/borders `#fbf8ff` / `#e8dcf9`. Keep documentation cards and sidebar navigation groups clearly framed.

Organize the portal with clear groups for getting started, hosted checkout, integration, webhooks, reliability, and resources. Keep the direct API guide on one vertically scrollable page, including its workflow, examples, endpoint contracts, catalog, and limits; do not add one menu entry per endpoint. Keep every section tied to SendFlow features verified in the code.

Public documentation must use the SendFlow brand exclusively. Do not mention payment providers, aggregators, or technical partners in prose, snippets, errors, examples, or labels. Operator names may appear only when needed to explain a verified payer flow.

**Why:** the user wants external references to guide typography while preserving SendFlow's identity and says developers should read the complete direct API integration on one page instead of navigating many endpoint entries.

**How to apply:** use Inter only within the docs portal across desktop and mobile; keep the existing SendFlow palette and left-side expandable navigation. Keep Hosted Checkout separate, and place all direct API integration details in one scrollable guide. Use operator names only for verified payer instructions, and search public docs and examples for partner names before release.
